# Milestones — A Log of Completed Missions

> Every meaningful piece of work gets a dated entry. The pattern: `YYYY-MM-DD_<mission-slug>.md` in this directory.

---

## The Pattern

Each milestone file follows this structure:

```markdown
# YYYY-MM-DD — Mission Title

## The Mission
[1-2 sentences: what was the goal]

## What Was Delivered
[Bulleted list of artifacts, paths, sizes]

## Key Decisions
[3-5 decisions made during the work, with rationale]

## Outcomes (Measured If Possible)
[What changed, what improved, what was learned]

## Follow-Up
[What comes next, time-bound]
```

## Why a Milestones Log

Three reasons:

1. **Memory persistence.** The work outlives any single conversation. When Gabriel asks "what did we build?", the log answers.
2. **Compounding reference.** Each milestone is a worked example for the next one. Patterns that worked get reused. Patterns that failed get flagged.
3. **Audit trail.** If Hermes goes offline and a new agent picks up, the log is the history. "What has this partnership done? What worked? What didn't?"

The log is a read-mostly artifact. New entries get added. Old entries get corrected if needed (with a "corrected 2026-XX-XX" note at the bottom of the file). Entries don't get deleted.
